## About this project

- **Game:** MagicPocketPistol — a team battle royale in which, in the entrant's words, "players who are relatively weak at it still have something to do": knocked-out contestants turn into small animals that keep helping their team, and anything on the map can be loaded into the pistol as a magazine.
- **Theme:** Director's Cut. The entrant's reading, translated from their words: with AI's assistance, turning what was impossible into something possible, and presenting the world one has in mind better. The entrant's view (translated): "I think my design fits the theme."
- **Overview:** a short account of the whole jam that can be read on its own is in [`devlog/OVERVIEW.md`](devlog/OVERVIEW.md).
- **Engine:** Unreal Engine 5.9, packaged for Windows (Development build)
- **People:** one human entrant (design decisions, art direction, choosing and fixing the generated 3D models, playtesting, video, submission)
- **AI agents:**
  - Claude Code (Claude Opus 5.5; Claude Fable 5.2 on 2026-11-12 about 06:00–15:30 and on 2026-11-13 12:10–19:02, by the model named in each commit): architecture, nearly all of the game's own C++, code review, the design record
  - Codex (`gpt-6-astra`): implementation in the Unreal Editor through Unreal MCP, Play-In-Editor checks, builds, packaging and smoke tests
- **AI generators:** OpenAI Images API (`gpt-image-2`) for the concept and reference images, the HUD item icons and the hit patterns; Tripo (the contestant) and Hyper3D Rodin (buildings, furniture, props, the airdrop crate). All used only after the start.
- **How the agents worked together:** shared files instead of a shared chat; see "How the team works" under "Before the jam".

### How the team works

- **One human, two AI agents.** The entrant makes every design, scope and art decision, chooses and fixes the 3D models (generated with AI tools after the start), and does the playtesting, video and submission. Claude Code writes the rules and plans and reviews the work; Codex writes the scripts and runs the editor, builds and packaging. A conclusion that is not written there does not count.
- **One writer per file.** Each task in `STATUS.md` names the files it may change. One agent at a time holds the Unreal Editor; the other may only make read-only MCP calls. Packaging takes a lock file.

### 2026-11-12 00:33–01:34 — Moving to Unreal Engine 5.9

- **Goal:** Unreal Engine 5.9.0 came out just before the jam (installed on 11-10) with many new AI and MCP editor tools. The entrant wanted to use it, but every check so far had been done on 5.8.4.
- **What happened:** Claude proposed a gated upgrade: upgrade only the throwaway project, re-run four gates, and stay on 5.8.4 if any gate failed and could not be fixed. All four passed:
  - **MCP:** the Editor's MCP server came up on port 8010 and listed 105 toolsets (we had recorded 52 on 5.8), including Live Coding, NavMesh, AI (Behavior Tree, EQS), input, scene capture and performance tools.
  - **C++:** compiled with the Visual Studio 2022 toolchain. A `.cpp` change was hot-reloaded through the new Live Coding MCP tool in about 11 seconds, without restarting the Editor.
  - **Assets:** Epic's template characters and animations loaded; the FBX import script still produced one convex collision hull.
  - **Packaging:** 205 s, 330 MB ZIP (+3.6% over 5.8). Smoke tests passed on DirectX 12 and on forced DirectX 11, and the packaged game opened no MCP port.
- **How AI was used:** Claude Code first read the 5.9 engine source to predict what would break, then ran all four gates itself. It drove the Editor through MCP with a small JSON-RPC client that checked, before every call, that port 8010 belonged to the Editor it had started.
- **Human decisions:** the entrant chose to try 5.9; dropped the test of two Fab animation packs because the theme was not known yet; gave the job to Claude instead of Codex to save time; and approved the switch after all gates passed.
- **Problems and fixes:**
  - 5.9 reads the MCP server settings from a new config section and ignores the old one, so the Editor would not have started MCP on our port. The bootstrap script now picks the section that matches the engine's source, and on 5.9 it also sends a short rules summary to MCP clients when they connect.
  - The first 5.9 Editor launch stopped at a "Target Upgrade Required" dialog: an upgraded project needs the 5.9 build settings in its target files. Fixed in the test project; projects created from a 5.9 template already have them.
  - 5.9 refuses the newest MSVC compiler because of an optimizer bug; Unreal Build Tool picked the installed Visual Studio 2022 toolchain on its own.
- **Evidence:** `relay\J-20261112-01.md`; Kit `801053b`, `3cad57b`; test project `c5499ec` to `15897cc`; logs in `Builds\logs`.

### Other problems solved before the jam

- In UE 5.8, a scripted FBX import without an explicit factory goes through Interchange and silently drops `UCX_` collision. The import script forces the legacy FBX importer and reports an error, without saving, if the mesh ends up with no convex hull.
- MCP tool descriptions come back machine-translated into the Editor's language, with mistakes, so the agents call tools only by toolset name, tool name and schema.
- Codex could not see the MCP server at first because its setting lived in a subfolder. Both agents now open their sessions in the jam root, where the MCP settings live.
- Our first count of the UE 5.9 toolsets (111) was wrong: the counting pattern also matched six lines inside tool descriptions. Counting only dotted toolset names gives 105, which a later native call confirmed.
